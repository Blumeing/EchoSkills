# 交互式HTML产品原型生成

根据产品需求，生成完整的、可直接运行的单文件HTML产品原型。

## 核心工作流程

1. **理解需求** - 明确用户需要展示的产品功能和界面元素
2. **整理规则与设计布局** - 按下述结构化标注规范整理规则，识别矛盾和缺失，再规划界面与说明的对应关系
3. **编写代码** - 生成符合所有技术规范的完整HTML文件
4. **验证检查** - 验证说明与实际演示行为一致，以及连线、定位、视图切换和响应式表现

## 结构化标注规范（必须严格执行）

以业务模块为主标注，复杂操作可增加子标注。每个模块检查以下维度，按适用情况展示，不要求简单图标或按钮重复填写全部分类。

| 分类 | 内容 |
| --- | --- |
| 定义与范围 | 功能用途、业务对象、项目及用户范围 |
| 加载逻辑 | 加载时机、数据筛选条件、人员归属规则、刷新时机 |
| 页面元素 | 字段名称、格式、枚举值、显示条件；明确本期支持值与完整字典的区别 |
| 交互规则 | 操作触发条件、跳转目标、执行结果、成功后的界面和数量更新 |
| 排序与数量 | 主次排序、展示上限、分页方式、数量统计口径 |
| 权限说明 | 查看和操作权限、无权限时的隐藏或禁用方式；区分人员归属与操作授权 |
| 状态与异常 | 加载中、空数据、加载失败、数据失效及恢复方式 |

- 将排序、数量和空状态归入对应分类，不集中堆放在“其他”。正式说明中的“略”应替换为具体规则、明确的公共规范引用或“待补充”。
- 已确认规则忠实保留；缺失规则标记“待确认”；为交互演示补充的行为标记“演示假设”。不得将假设写成已确认需求。
- 发现范围、类型、状态或权限规则冲突时，集中列出待确认事项；可继续实现不依赖这些事项的内容，不自行消解业务矛盾。
- 示例业务不能成为通用规则。例如通知模块应核对：本期通知类型与完整字典、未处理状态判定、多位专家的签署责任、数量的项目及用户范围、时间字段、更多页范围、按钮条件和处理后刷新。没有输入依据的答案保持待确认。
- 关键规则应能通过交互或独立的演示状态入口验证。演示工具放在原型说明区，不混入产品用户流程；未实现的操作明确说明演示范围。

## 批注编辑与保存（必须严格执行）

- 提供“编辑批注”模式，支持新增、修改、删除及撤销批注操作。
- 新增批注时，用户直接在产品界面上选取文字、字段、按钮、卡片或模块；悬停时高亮选取范围，点击后创建批注，按 `Esc` 取消选取。
- 为每条批注生成稳定的内部 ID，并保存组件关联和卡片顺序。界面序号按全部卡片的顺序从 1 连续显示。拖动排序或删除后立即重新编号，卡片、页面标记、连线同步更新。重开 HTML 后恢复已保存的顺序、关联和内容。
- 批注内容沿用结构化分类，可编辑标题及各分类正文。每个有正文的小节按顺序编号，标题独占一行，正文另起一行并保留换行。空小节不显示。
- 编辑过程中自动保存浏览器草稿，刷新后可恢复；明确区分“草稿已保存”与“原文件已保存”。
- 点击“保存批注”时，将修改写回原 HTML。首次保存由用户选择原文件并授予写入权限；同一页面后续保存复用授权。写入前校验所选文件属于当前原型。
- 排序、删除、撤销或重新关联后，通过“保存原文件”写入变更。批注工具栏提供“导出副本”，下载可独立打开的 HTML，包含当前批注内容、卡片顺序和组件关联，原文件保持不变。
- 写入成功后才提示“已保存到原文件”；用户取消、权限不足或写入失败时，保留编辑草稿并说明原因。
- 浏览器不支持原文件写入时，明确提示使用支持该能力的浏览器，不得将下载副本或保存浏览器草稿视为写回原文件。

### 编辑体验与验收

- 在卡片标题旁提供拖动手柄，允许调整卡片顺序并撤销排序。
- 点击批注卡片序号定位到关联组件。跨页时先打开对应页面，再定位组件。
- 点击产品界面上的批注序号，打开批注栏、展开对应卡片并进入重新选取模式。点击新组件更新关联，按 Esc 取消并保留原关联。
- 在“功能批注”标题下提供“显示范围”，默认“当页批注”，可切换到“全部批注”。公共导航上的批注在各页可见。切换范围仅过滤卡片，保留全局顺序及编号。

- 编辑工具集中在批注区；选取模式下拦截产品操作，退出后恢复原有交互。
- 保持黄色圆形悬浮按钮，以“原型”／“批注”切换视图。
- 验证新增、修改、删除、拖动排序、重新编号、双向定位和重新关联、显示范围、撤销、草稿恢复、原文件写入及副本重新打开后的内容、顺序与关联。确认取消或失败时草稿仍可恢复。

## 布局规范（严格执行）

### 整体结构

- **左右分栏布局**
  - 左侧：使用剩余空间展示产品主体界面
  - 右侧：默认约360–480px，支持拖动调整，展示结构化说明；空间不足时使用抽屉或上下布局
  - 每个模块一张琥珀色说明卡，按分类分节并支持折叠；卡片序号与页面序号的操作遵循“编辑体验与验收”
- **分隔线**：左右两栏之间有清晰的垂直分隔线
- **滚动方式**：两栏独立滚动，仅在主动定位标注时滚动对应区域

### 连线功能（必须严格执行）

使用SVG技术绘制连线，确保连线清晰可见且不遮挡内容。

**连线规则：**
- 标注数量由业务复杂度决定，覆盖主要业务模块及关键操作，不固定为2–4个
- 默认只显示当前选中或悬停标注的连线，避免多条连线遮挡界面
- 连线的**起始点**必须精确连接到左侧元素的右侧边缘中点
- 连线的**结束点**连接右侧说明卡标题旁编号的左侧边缘中点，不连接整张卡片的中点
- 连线采用平滑的贝塞尔曲线，避免生硬的直角转弯
- 连线线条粗细为 2px

**交互效果：**
- 当鼠标悬停在左侧元素上时，对应的连线加粗并高亮显示
- 当鼠标悬停在右侧说明文字上时，对应的连线和左侧元素也会高亮显示

**连线标注：**
- 每条连线旁边添加小的数字编号，与右侧说明的编号对应

## 视图切换按钮规范

- 视图名称统一为“原型”和“批注”：原型视图展示产品界面并保留标注编号；批注视图同时展示产品界面和结构化标注说明。

- 桌面和手机端统一使用圆形悬浮按钮，固定在视口右下角；两种视图下均保持可见，滚动时不随内容移走。
- 使用与右侧标注一致的黄色/琥珀色系：浅黄背景 #FEF3C7、琥珀边框 #F59E0B、深琥珀文字 #92400E；悬停背景 #FDE68A。禁止使用蓝色矩形按钮。
- 建议直径56px，距右侧和底部24px，圆角50%，配轻阴影；按钮文字使用目标视图名称：当前为“批注”视图时显示“原型”，当前为“原型”视图时显示“批注”。点击页面序号打开批注栏时，同步更新按钮文字。提供可访问名称、提示和键盘焦点样式；浮层位置避免遮挡主要操作。

## 响应式设计规范

### PC端
- 保持上述左右分栏布局
- 提供"切换视图"按钮，允许用户在"原型"和"批注"之间切换
- 原型视图保留页面批注序号，点击后打开批注栏并进入重新选取模式。

### 手机端
- 自动切换为上下布局
- 上方展示产品主体界面，下方展示功能说明
- 连线功能自动隐藏
- 点击页面批注序号展开下方的对应卡片并进入重新选取模式。
- 提供"切换视图"按钮，允许用户在"原型"和"批注"之间切换

## 技术栈要求

1. **纯前端实现**：使用纯HTML、CSS和原生JavaScript，不依赖任何外部框架
2. **样式**：使用Tailwind CSS v3，通过CDN引入
3. **图标**：使用Font Awesome图标库，通过CDN引入
4. **代码结构**：
   - HTML结构语义化，使用适当的标签
   - CSS样式内联在`<style>`标签中
   - JavaScript代码内联在`<script>`标签中
   - 业务代码整合在一个HTML文件中；以上CDN资源需要联网。用户要求离线时改用内联样式及内联图标，不声称CDN版本可完全离线运行

## 样式与视觉规范

### 配色方案
- 如果用户指定了色系则用用户指定的色系，否则用下面默认的色系
- **主色调**：蓝色 `#165DFF`
- **辅助色**：浅灰色 `#F5F7FA`、深灰色 `#333333`
- **强调色**：绿色 `#00B42A`（成功状态）、红色 `#F53F3F`（错误状态）

### 其他样式要求
- 右侧的功能说明区要用琥珀色系，跟左侧内容区区分开！
- **字体**：系统默认无衬线字体
- **间距**：以 8px 为基本单位，保持一致的间距系统
- **阴影**：适当使用轻微阴影增强层次感
- **整体风格**：简洁、现代、专业的产品原型风格

## 输出要求

1. 输出完整的HTML文件代码
2. 代码开头添加简短说明，介绍原型的功能和使用方法
3. 确保所有连线的起始和指向位置完全正确
4. 确保在不同屏幕尺寸下都能正常显示和交互

## 注意事项

- 连线在DOM渲染后计算，滚动、窗口变化、面板拖动、说明折叠和视图切换后重新计算；任一端隐藏或离开可视区域时隐藏连线
- 编号按钮独立于SVG且可键盘操作；事件只绑定一次，避免resize时重复绑定。面板调宽提供键盘操作方式
- 确保SVG的 `pointer-events-none` 不会阻挡下方元素的交互
- 移动端切换视图时，需要平滑过渡动画
- 所有元素ID和数据属性命名要清晰，便于连线脚本定位
